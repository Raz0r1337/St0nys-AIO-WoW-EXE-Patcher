Patch again on "no change" instead of only quitting

If the selection is exactly the state of Wow.exe, the patcher used to stop
with "No change compared to the current Wow.exe". The patch state only
remembers which patches are in with which values, so after an update of
the patcher a patch with new code (e.g. No. 68) was never written again.

- Without -Unattended the patcher now asks: patch again (Y/J) or quit (N).
  Patching again lists the selected patches, shows the usual notes and the
  confirmation, backs up the current Wow.exe as Wow.exe.BAK and applies
  all selected patches freshly to the original.
- With -Unattended nothing changes: no question, exit code 0.
- README DE/EN: new point "No change" under the patch state.
